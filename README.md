# Watch Demo — магазин в Telegram

Бот-магазин на aiogram 3 с витриной Mini App: каталог, корзина, оформление
заказа, приём оплаты и админка — в одном процессе, который разворачивается
на одном контейнере.

**Живой бот:** [@watch_demo_shop_bot](https://t.me/watch_demo_shop_bot) ·
**витрина:** https://watch-demo-shop.onrender.com

Каталог часов вымышленный — это демонстрационная витрина, которую я
кастомизирую под товар заказчика.

## Что умеет

**Покупателю.** Каталог по категориям с фото, характеристиками и остатком;
корзина; оформление заказа пошагово (способ получения, адрес, контакт); оплата
по реквизитам с отправкой чека; свои заказы с историей статусов и отменой,
пока заказ не собран. Всё то же самое доступно двумя способами — кнопками в
чате и в витрине Mini App, расчёты у них общие, поэтому суммы не расходятся.

**Владельцу.** Приём заказов с уведомлением, подтверждение оплаты по чеку,
ведение заказа по статусам, ввод трек-номера, отмена с причиной, добавление
товаров и правка остатков прямо в чате.

**Жизненный цикл заказа.** Восемь статусов, переходы описаны схемой в
[`bot/utils/lifecycle.py`](bot/utils/lifecycle.py) — запрет отправить
неоплаченный заказ следует из самого графа, а не из россыпи проверок по
обработчикам. Каждая смена статуса пишется в историю и уходит покупателю
сообщением, текст которого зависит от способа получения. Неоплаченные заказы
отменяются фоновой задачей через `UNPAID_TTL_MINUTES`, товар возвращается
в наличие.

**ИИ-консультант** (опционально). Модель отвечает на вопросы о товарах и
собирает корзину через function calling: `search_products`, `product_details`,
`add_to_cart`, `show_cart`, `call_manager`. Цены, остатки и содержимое корзины
считает сервер — модель только вызывает функции, поэтому выдумать цену или
скидку она не может. Есть ограничение числа запросов на пользователя, чтобы
один настойчивый посетитель не потратил бюджет владельца.
Провайдер выбирается настройкой: GigaChat (оплата в рублях, без VPN) или
Gemini. Новый подключается классом на несколько десятков строк — остальной
код о провайдере не знает.

## Стек и решения

Python 3.12, aiogram 3, FastAPI, SQLAlchemy 2 (async), SQLite, Uvicorn.

- **Один процесс на всё.** `python -m api` поднимает витрину и бота вместе:
  разворачивать нужно один сервис, а не два. `python -m bot` запускает только
  бота, если витрина не нужна.
- **Webhook на хостинге, long-polling локально.** Бесплатные тарифы усыпляют
  контейнер без входящих запросов, и спящий polling молча перестаёт забирать
  апдейты; webhook процесс будит.
- **Подпись Telegram проверяется на сервере.** `initData` Mini App сверяется
  HMAC-ом от токена бота, срок жизни подписи ограничен. Без этого витрину
  можно было бы открыть из обычного браузера от чужого имени.
- **Сумма фиксируется на подтверждении.** Клиент присылает сумму, которую
  видит на экране, сервер сверяет её с пересчитанной и отказывает при
  расхождении: иначе правка цены между показом корзины и нажатием кнопки
  тихо меняет чек покупателю.
- **Версия статики машинная.** Адрес `app.js` и `style.css` несёт отпечаток
  содержимого, поэтому webview Telegram не показывает старую версию после
  обновления.
- **Ограничитель частоты запросов** к API витрины с учётом заголовков
  обратного прокси.

## Запуск

```
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
python -m api
```

В `.env` обязательны `BOT_TOKEN` (от [@BotFather](https://t.me/BotFather)) и
`ADMIN_IDS`. Остальное — с рабочими значениями по умолчанию; все переменные
описаны в [`.env.example`](.env.example).

При пустой базе заливается демонстрационный каталог, так что бот отвечает
сразу после первого запуска.

Развёртывание на Render описано в [`render.yaml`](render.yaml) — сервис
поднимается из репозитория без ручной настройки в панели.

## Тесты

Тесты — самостоятельные скрипты без зависимости от тестового фреймворка,
каждый печатает итог строкой `OK: N FAIL: N`:

```
.venv\Scripts\python.exe smoke_test.py
```

| Скрипт | Проверок | О чём |
|---|---|---|
| `api_test.py` | 87 | HTTP API витрины, подпись, лимиты |
| `smoke_test.py` | 55 | каталог, корзина, заказ, админка |
| `ai_test.py` | 44 | консультант на подставной модели, квоты |
| `lifecycle_test.py` | 43 | матрица переходов 8×8×3 |
| `chat_parity_test.py` | 35 | чат и витрина дают одинаковый заказ |
| `features_test.py` | 34 | поиск, остатки, доставка |
| `hardening_test.py` | 25 | враждебные входные данные |
| `bug_test.py`, `bug2_test.py` | 17 | регрессии по найденным багам |
| `assets_version_test.py` | 10 | отпечаток статики |
| `wiring_test.py` | 14 | сборка роутеров, фильтры, callback_data |
| `keepalive_test.py` | 9 | самопинг против засыпания контейнера |

Итого 373 проверки. Отдельно лежит `ai_eval.py` — живой прогон консультанта на
реальной модели с попытками увести её с темы и выманить чужие данные;
он требует ключа и гоняется руками перед сдачей.

## Структура

```
bot/
  config.py        настройки из .env
  db/              модели SQLAlchemy и репозиторий
  handlers/        start, catalog, cart, checkout, admin, ai
  keyboards/       инлайн-клавиатуры
  middlewares/     сессия БД на апдейт
  utils/           lifecycle, sweeper, keepalive, notify, seed
  ai/              провайдеры LLM, инструменты, цикл агента
api/               FastAPI: маршруты витрины, лимиты, webhook бота
webapp/            витрина Mini App (чистый JS и CSS, без сборки)
```

## Под заказ

Витрина настраивается под товар заказчика: каталог, валюта, тексты, платёжные
реквизиты, оформление. Готов дорабатывать под задачу — приём платежей через
YooKassa, интеграция с CRM, другой мессенджер.
